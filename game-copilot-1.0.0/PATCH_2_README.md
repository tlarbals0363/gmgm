# Game Copilot 1.0.2 — 2번 작업 관리자 패치

대상: 1번 패치가 적용된 1.0.1. 사용자께서 올린 game-copilot-1.0.0 (2).zip은
1번 패치 파일과 모두 일치하는 것을 확인했습니다. 폴더 이름은 1.0.0이어도 괜찮습니다.
이 ZIP은 변경 파일만 포함하며 단독 설치본이 아닙니다.

## 덮어쓰기 적용

1. 프로그램과 샘플 브리지 서버를 종료합니다.
2. 기존 프로그램 폴더를 복사해서 백업합니다.
3. 패치 ZIP을 임시 폴더에 풀고 안의 내용 전체를 기존 프로그램 폴더 안에 복사합니다.
   run-free.cmd, run-paid.cmd가 있는 위치가 대상입니다.
   copilot / examples / tests는 기존 폴더와 병합하고 같은 파일은 덮어씁니다.
   기존 폴더를 삭제하거나 패치 파일만 있는 새 폴더에서 실행하지 마세요.
4. 평소 쓰던 실행 파일을 실행합니다. 창 제목과 상단이 1.0.2이면 적용되었습니다.

API 키 재입력이나 pip 설치는 필요하지 않습니다.
%APPDATA%\GameCopilot1, free.key, paid.key, workspace.json, runtime.txt는 건드리지 않습니다.
.env, .env.nvidia, .venv도 패치에 포함하지 않습니다.
키 저장 코드 storage.py, API 호출 코드 ai.py 및 실행 스크립트도 변경하지 않았습니다.
같은 PC와 Windows 계정에서 저장된 키/프로필을 사용합니다.
환경변수로만 키를 사용했다면 기존 실행 환경을 유지하세요.

## 무료/유료 각각 확인하기

1. 무료판을 켜고 '데모 기지' → '연결 / 데모 초기화'.
2. '데모 규칙 엔진' 체크 → '자동 시작'.
3. 로그에 작업 ID와 '시작 요청 → 접수됨 → 성공'이 표시되고 연구 10으로 승리하는지 확인.
4. 창을 닫고 유료판에서도 같은 과정을 수행.

이 과정은 API를 사용하지 않으므로 키 인증이나 모델 접근 권한을 검증하지 않습니다.
실제 API는 '모델 / API 키'의 빠른/심화 모델 시험으로 각각 확인할 수 있습니다.
또는 데모 규칙 엔진을 끄고 '한 번 분석'을 실행하면 실제 모델 판단을 확인합니다.
심화 모델은 한 번 분석에서 항상 호출되는 것은 아닙니다. 실제 API 시험에는 사용량이 발생합니다.
무료판과 유료판은 동시에 열 수 없습니다.

선택: 터미널에서 python -m examples.task_lifecycle_demo
장기 작업의 상태 전환을 모의로 보여주며 API와 실제 게임을 사용하지 않습니다.

## 구현된 범위

- 고유 작업 ID, 시작/접수/진행/성공/실패/취소 요청/취소 확인/결과 불명 관리.
- 미완료 작업이 있으면 중복 시작 차단. 오래된/중복 응답은 무시.
- 취소 요청과 실제 중단을 구분하고, 접수와 성공을 구분.
- 기존 단발 행동을 작업 관리자로 추적하고 UI 로그에 표시.
- 결과 불명 시 새 행동과 재연결을 막아 무작정 재실행하지 않음.

작업 기록은 현재 실행 세션에만 남습니다. 결과 불명 상태에서는 게임에서 실제 결과 및
동작 중단을 확인한 뒤 프로그램을 재시작하세요. 재시작은 원격 작업 취소가 아닙니다.
작업 관리자 인터페이스와 제한은 TASK_MANAGER.md에 있습니다.

실제 장기 작업 전송, 원격 취소, 연결 끊김 자동 중단, 실시간 게임 조작은 이번 범위에 없습니다.
다음은 3번 작업 취소와 연결 끊김 처리입니다.

## 검증

기존 38개 + 새 14개 = 총 52개 테스트 통과.
무료/유료 모드의 API 없는 데모 승리, 상태 전환, 중복 시작, 늦은 응답,
취소와 성공의 경합, 결과 불명 차단을 확인했습니다.
원본에 패치를 덮어쓴 임시 설치본에서도 테스트 및 키/설정 대용 파일 바이트 보존을 확인했습니다.
실제 API 호출, Windows GUI와 DPAPI 복호화, 실제 게임 플레이는 이 환경에서 검증하지 못했습니다.
