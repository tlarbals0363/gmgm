# Game Copilot 1.0.3 — 3번 작업 취소와 연결 끊김 처리

**대상은 이번에 첨부한 `game-copilot-1.0.0 (3)(1).zip`입니다. 내부 버전 1.0.2, 2단계까지 완료된 소스를 기준으로 만들었습니다.**
폴더 이름이 1.0.0이어도 괜찮습니다. 예전 0.x, 원본 1.0.0, 다른 1.1 확장안과 섞지 마세요.
이번 ZIP은 변경/추가 파일만 담은 덮어쓰기 패치이며 단독 설치본이 아닙니다.

## 적용

1. Game Copilot 창과 실행 중인 샘플 브리지를 종료합니다.
2. 현재 프로그램 폴더를 복사해 백업해 둡니다.
3. 패치 ZIP을 임시 폴더에 풀고 **안의 파일과 폴더를 모두** 복사합니다.
4. 기존 `run-free.ps1`, `run-paid.ps1`이 있는 폴더 안에 붙여넣습니다.
5. `copilot`, `examples`, `tests`는 기존 폴더와 병합하고 같은 파일은 교체하세요.
   기존 폴더 전체를 삭제하거나 `copilot` 안에 다시 `copilot`을 넣지 마세요.
6. 기존 방식으로 실행합니다. 창 제목과 상단에 **1.0.3**이 보이면 적용되었습니다.

무료:
```powershell
powershell -ExecutionPolicy Bypass -File .\run-free.ps1
```
유료:
```powershell
powershell -ExecutionPolicy Bypass -File .\run-paid.ps1
```

Python/pip 재설치나 API 키 재발급·재입력은 필요하지 않습니다.

## 키·프로필 보존

`copilot/storage.py`, `copilot/ai.py`, 실행 스크립트는 변경하지 않았습니다.
`%APPDATA%\GameCopilot1`의 저장 위치와 DPAPI 형식도 그대로입니다.
`free.key`, `paid.key`, `workspace.json`, `runtime.txt`, `.env`, `.env.nvidia`, `.venv`는 패치에 없습니다.
같은 PC·Windows 계정에서 기존 키·프로필·메모·모델 설정·대기시간을 유지합니다.
환경변수로만 키를 사용했다면 기존 실행 환경을 유지하세요. 데이터 폴더는 지우지 마세요.

## 이번 3단계의 범위

- 본체 중지를 지원 연결 모듈에 실제 취소 요청으로 전달.
- 취소 의도 / 원격 중단 확인 / 결과 불명을 구분. 접수 ACK를 성공으로 처리하지 않음.
- 모듈이 본체와 별도로 유지 신호를 감시하고 만료 시 작업 중단.
- 시작 전 도착한 취소를 기억하여 뒤늦은 시작 요청 차단.
- 종료·취소·만료된 작업은 늦은 유지 신호로 되살리지 않음.
- 작업 결과 확인은 읽기 전용이며 작업 시작을 재전송하거나 유지 신호를 보내지 않음.
- 기존 v1 단발 행동과 2단계 작업 관리자 상태·중복 실행 방지 유지.
- UI에는 이번 검증에 필요한 시험/결과 확인 버튼만 추가. 기존 프로필 구조 유지.

**4번 상황 변화 AI 호출, 5번 장애물·위험 실시간 제어 데모, 6번 전용 화면/프로필 개편, 7~9번 실제 게임 연결·기억 개선은 포함하지 않았습니다.**
이번 시험은 단순히 숫자를 증가시키는 가상 작업입니다. 이동·전투 게임이 아닙니다.
실시간으로 선언된 연결은 기존과 동일하게 조언 전용입니다. 취소 가능한 턴제 장기 작업 규격과 시험 모듈만 연결했습니다.
무료 API 응답 속도를 개선하는 패치도 아닙니다.

## 확인 1: 중지 버튼

무료·유료 어느 모드에서든 아래 과정은 API를 사용하지 않습니다. 기존 게임 프로필에 연결할 필요도 없습니다.

1. `게임 / 코치`의 **3번 중지 시험 → 시험 작업 시작**을 누릅니다.
2. 아래 로그에 **시작 요청 → 접수됨 → 진행 중**이 보이는지 확인합니다.
3. 상단 **중지**를 누릅니다.
4. 로그에 **취소 요청 → 취소 확인**이 표시되는지 확인합니다.
5. 작업이 끝난 뒤 **작업 결과 확인**을 누르면 카운터 값과 `조작 유지: False`가 표시됩니다.

취소 직전에 작업이 이미 끝났다면 성공으로 남습니다. 실제 성공을 취소로 바꾸지 않습니다.

## 확인 2: 연결 끊김

1. **시험 작업 시작**을 다시 누르고 진행 로그가 뜰 때까지 기다립니다.
2. **시험 통신 끊기**를 누릅니다. 시험용 유지 신호/주기적 상태 조회가 중단됩니다.
3. 본체의 상태는 **결과 불명**입니다. 실제 중단을 아직 확인하지 못했기 때문입니다.
4. 약 **4초** 기다린 뒤 **작업 결과 확인**을 누릅니다.
5. **취소 확인**, **연결 유지 신호 만료**, `조작 유지: False`를 확인합니다.

모듈의 독립 감시기는 마지막 유지 신호로부터 3초가 지나면 작업을 중단합니다. 시험 루프는 50ms 간격이며 OS 스케줄링 지연이 있을 수 있습니다.
시간이 지났다는 이유만으로 본체가 취소 성공을 추정하지 않습니다. 결과 조회가 실패하면 결과 불명을 유지하고 다음 실행을 막습니다.
결과 확인을 너무 빨리 누르면 아직 진행 중일 수 있습니다. 이 조회는 유지 신호를 연장하지 않습니다.

`시험 통신 끊기`는 내부 카운터에만 적용하는 진단 기능입니다. 실제 게임/다른 프로필에 네트워크 장애를 일으키지 않습니다.

## 터미널에서 동일 시험

프로그램 폴더에서:
```powershell
python -m examples.cancel_disconnect_demo
```
API 없이 두 시나리오를 실행하고 PASS를 출력합니다.
현재 터미널의 Python이 다르다면 기존에 사용하던 Python 실행 파일로 같은 `-m` 명령을 실행하세요.

외부 HTTP 참조 브리지(개발자용):
```powershell
python -m examples.cancel_bridge
```
콘솔의 주소/게임 ID/브리지 토큰을 bridge 프로필에 넣을 수 있습니다. 이것도 가상 카운터일 뿐 실제 게임 모드는 아닙니다.
해당 프로필에서 AI 분석을 누르면 API를 사용하므로, API 없는 중지 시험은 위 전용 버튼/명령을 이용하세요.
샘플 서버는 기본 127.0.0.1:8767이며 Ctrl+C로 종료합니다.

## 제한

- 기존 `/v1/action`은 단발 실행 완료 계약입니다. 이미 전달된 단발 행동에 원격 취소가 새로 생기는 것은 아닙니다.
- 네트워크가 완전히 끊기면 본체의 취소 요청 자체도 도달하지 않을 수 있습니다. 이때 실제 중지는 모듈의 독립 감시기가 담당합니다.
- 미래 실제 게임 모듈도 이 규격의 감시·조작 해제를 구현해야 합니다. capability 문자열만 붙인다고 게임이 안전하게 멈추지는 않습니다.
- 본체 강제 종료 후에도 외부 모듈은 유지 신호 만료로 중단해야 합니다. 모듈 자체가 멈추는 장애까지 Python 본체만으로 해결하지는 못합니다.
- 중지는 이미 적용된 게임 행동이나 API 비용을 되돌리지 않습니다. 창 종료는 취소를 요청하고 최대 약 3초 확인 후 닫습니다.
- 작업 기록은 2단계와 같이 현재 실행 세션에만 있습니다. 재시작으로 결과 불명 기록이 사라져도 원격 작업이 취소되었다고 가정하지 마세요.

## 검증

기존 52개와 신규 취소·단절 테스트를 포함한 **73개 테스트 통과**.
HTTP 왕복, 별도 클라이언트 프로세스 종료 후 독립 중단, 중복 시작, 취소/시작 경합,
늦은 성공/유지 신호, 잘못된 응답 ID, 취소 확인 실패 시 결과 불명, 기존 무료/유료 데모 회귀를 검사했습니다.
원본에 패치만 덮어쓴 임시 설치본으로도 테스트합니다. 키/설정 보존은 실제 키가 아닌 대용 파일로 확인합니다.
실제 사용자 키 API 호출, Windows GUI·DPAPI 실제 복호화, 상용 게임 플레이는 이 환경에서 검증하지 못했습니다.

변경 파일과 SHA-256은 `PATCH_INFO.json`에 있습니다. 이 파일은 기록용이며 자동 설치기는 아닙니다.
되돌릴 때는 프로그램을 종료하고 백업한 1.0.2 소스를 복원하세요. 사용자 데이터 형식은 바뀌지 않았습니다.
